### Duplicate / exposition / typing defects

- **Duplicate metric name:** `MetricAmbiguousOps` (L57) and `MetricAmbiguousOpsTotal` (L63) are both `"syncfs_ambiguous_operations_total"`. `SetFromStats` L104 uses the latter; scrapers see one series with two Go aliases (confusion + silent aliasing if both ever populated).
- **Missing HELP (and EOF-adjacent) markers:** `Prometheus()` L91 emits only `# TYPE %s gauge` + sample per series (sorted, L88). No `# HELP <name> <doc>` lines, no histogram `_bucket{le="+Inf"}` contract, no trailing `# EOF`-equivalent marker discipline expected by `client_golang` exposition. `Observe` comment “HELP text pinned by catalogue order” (L73) is false — no HELP text exists. `observability_test.go:9-23` asserts TYPE-only output, so the test enshrines the gap.
- **Gauges-vs-counters misuse:** L91 hardcodes `# TYPE %s gauge` for every series. `…_total` (`AmbiguousOps`, and if it existed `ChunkChecksumFailures`) are counters by Prometheus convention (`_total` suffix + `counter` TYPE); `LeaderQuorum`/indexes/lag are gauges. Today an alert on `rate(syncfs_ambiguous_operations_total[5m])` would be invalid against a `gauge` exposition; `increase()` on a gauge is undefined across scrapes if the value ever resets.
- **Dropped fields (silent):** `FollowerLag` (L24) and `ChunkChecksumFailures` (L29) are populated nowhere in `SetFromStats` (L97–109). A caller filling `Stats` in full still loses those two signals with no compile-time or test-time warning (`TestPrometheusRendersCatalogue` sets only 4 of 13 fields, L11).
- **Dead hooks:** `Collector.g/vol/lockmgr` (L41–43), `gcStats` (L47), `ErrCollectorClosed` (L112), `var _ = time.Now` (L114) — speculative wiring for M5 with no consumer; `volume` + `locks` imports (L15–16) exist only for these dead fields, creating an import cycle risk if ever used.
- **Unit/name drift:** `MetricLeaseRevokeWait`/`MetricLockWait` are `_ms` gauges; per Prometheus practice latency is base-unit seconds histograms. `MetricFreeBytes` is `_bytes` while `MetricCertificateExpiryHours` is `_hours` (human unit, not seconds) — inconsistent with the ops-gate `_bucket` + seconds contract.
