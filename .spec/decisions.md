Append-only. One entry per fork-closing decision. Each entry must cite its evidence file in `research/`.

## D-001 (2026-11-08) — Design fork closed: FUSE strict volume is the MVP data path; native-directory watcher is superseded for MVP scope.

**Context.** Two camps claimed the SyncFS name with irreconcilable data paths (FUSE interception vs native-dir watcher), consensus libraries (etcd/raft/v3 vs hashicorp/raft), transports (QUIC push/pipeline vs pull-from-journal), consistency (quorum-durable-before-ack vs bounded-loss async+quarantine), fencing tokens (Raft term/index vs per-directory epoch), and product shapes (single strict volume vs per-directory modes). Evidence in `research/07-design-fork-reconciliation.md` §2 (primary sources only: inotify.7, fanotify.7, close.2, nfs.5, etcd-io/raft README, hashicorp/raft README+config, hanwen/go-fuse README+pkg.go.dev, libfuse README, quic-go README, DRBD/Ceph/Gluster upstreams) proves a watcher can never deliver quorum-durable-before-ack (post-hoc, lossy, racy, mmap-blind; close completes locally; NFS coherence windows), that FUSE+etcd/raft/v3 can deliver it at priced cost, that the library choice maps exactly onto the camps (etcd deterministic core permits payload-before-reference + refuse-to-campaign; hashicorp integrated FSM/NotifyCh fits per-directory leases as FSM data), and that every shipped strong POSIX shared-directory system owns the op path (GlusterFS FUSE, CephFS MDS) while every native-dir async system accepts bounded loss (DRBD Protocol A).

**Decision.** The unified baseline in `research/07-design-fork-reconciliation.md` §3.5 is adopted: MVP = Camp A data path (FUSE mount, etcd/raft/v3 per volume, quic-go QUIC+mTLS, Pebble, BLAKE3 64 KiB chunks, quorum-durable writes, learner-first admission, one strict volume) with Camp B's node-state taxonomy, quarantine discipline, POSIX-apply requirements, and witness/learner vocabulary folded in as the operability layer. Camp B's watcher mutation path, hashicorp/raft MVP selection, pull-based steady-state transport, per-directory epoch fencing token, and per-directory async modes are superseded for MVP scope and deferred to post-MVP bounded-loss tiers under separate contracts. File dispositions in §4 of that document are adopted (ARCHIVE `.spec/directory-replication-daemon.md`, `.spec/consensus-layer.md`, `arch/architecture-proposal.md` with the exact banners; SUPERSEDE README product definition; MERGE specs/docs as listed).

**Consequences.** (1) The north star "acknowledged mutations durably replicated" is honored only by the FUSE path — any future async tier must carry a distinct name/contract and must never alias the strict volume. (2) Reopening a watcher mutation path, hashicorp/raft MVP selection, or epoch fencing for strict scope requires a new decision that explicitly revises either the north-star contract or §3.1's proof. (3) MVP perf gates (`.spec/technical_spec.md` §11) are the acceptance test for FUSE overhead — looseness there is an SLO change, not an architecture change.

**Adopted terms:** LEADER / FOLLOWER / FENCED / CANDIDATE / CATCHING_UP / QUARANTINED / HALTED (state projection over Raft state + apply lag + integrity flags); quarantine for corrupt WAL/snapshots and stranded staged chunks; POSIX-apply vectors (mode bits incl. setuid/setgid/sticky, chown-before-chmod, ACL/xattr/symlink/hardlink/mtime, uid/gid consistency) as MVP acceptance; witness/learner vocabulary (etcd has no witness role — Inv.3 unchanged; witness is vocabulary only until a split-quorum amendment is written).
